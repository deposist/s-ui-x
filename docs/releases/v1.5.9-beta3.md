# Release Notes: v1.5.9-beta3

Release date: 2026-06-17

This release lets you update the panel **from the web interface**. Until now an update required the server console (SSH). No manual changes to the database, API, or configuration are required.

**EN**

## 1. Update the panel from the web UI

A new **Panel updates** card is available in **Settings → Maintenance**:

* **Pick a channel.** *Main* tracks stable releases; *Beta* tracks the newest release, including pre-releases. On the Beta channel a freshly-published stable supersedes the matching beta — for example, once `1.5.9` is out it is offered over `1.5.9-beta2`.
* **Check for updates.** Click **Check updates** to see the available version, whether it is stable or beta, and its release notes.
* **Update in one click.** Click **Update** and the panel downloads the new version, verifies it, replaces itself, and restarts on the new version — no console needed. Only newer versions are offered (no downgrades).
* **Nothing else changes.** Unlike the console updater, the web update never asks whether to change your admin login, password, or settings — your credentials and configuration are kept exactly as they were, and any required database migration runs automatically on restart.

## 2. Built to be safe

Applying an update runs freshly-downloaded code with the panel's privileges, so it is guarded carefully:

* **Admin-only, with confirmation.** Updating is available only to a signed-in administrator and additionally requires re-entering your password before it runs. You are warned that the panel and proxying will restart briefly (active client connections are interrupted and then restored).
* **Verified downloads.** The release artifact is fetched over verified HTTPS and checked against the release's published SHA-256 checksum *before* anything is replaced. If the check fails, the update is aborted and the running version is kept.
* **Safe to fail.** If an update cannot complete, the previous version keeps running. The replaced binary is backed up, and if a freshly-installed version repeatedly fails to start, it is automatically rolled back.
* **Audited.** Every check and update attempt — including rejected ones — is written to the audit log. Your password is never logged.

---

**Important:** no manual changes to the database, API, or configuration are required to use the new version. The in-panel update applies to the standard Linux service install.

**RU**

# Релиз v1.5.9-beta3: что изменилось

В этом релизе появилась возможность обновлять панель **прямо из веб-интерфейса**. Раньше обновление требовало консоли сервера (SSH). Ручные изменения в базе данных, API или конфигурации не требуются.

## 1. Обновление панели из веб-интерфейса

В разделе **Настройки → Обслуживание** появилась карточка **Обновления панели**:

* **Выбор канала.** *Main* отслеживает стабильные релизы; *Beta* — новейший релиз, включая предварительные. На канале Beta только что вышедшая стабильная версия имеет приоритет над соответствующей бетой — например, после выхода `1.5.9` она предлагается вместо `1.5.9-beta2`.
* **Проверка обновлений.** Нажмите **Check updates**, чтобы увидеть доступную версию, её тип (стабильная/предварительная) и описание изменений.
* **Обновление в один клик.** Нажмите **Update** — панель скачает новую версию, проверит её, заменит себя и перезапустится уже на новой версии, без консоли. Предлагаются только более новые версии (понижение невозможно).
* **Больше ничего не меняется.** В отличие от консольного обновления, веб-обновление не спрашивает, менять ли логин администратора, пароль или настройки — учётные данные и конфигурация остаются как были, а необходимые миграции базы данных применяются автоматически при перезапуске.

## 2. Сделано безопасно

Применение обновления запускает скачанный из сети код с привилегиями панели, поэтому оно тщательно защищено:

* **Только для администратора, с подтверждением.** Обновление доступно только аутентифицированному администратору и дополнительно требует повторного ввода пароля перед запуском. Вы предупреждаетесь, что панель и проксирование кратковременно перезапустятся (активные соединения клиентов прервутся и затем восстановятся).
* **Проверенная загрузка.** Артефакт релиза скачивается по защищённому HTTPS и сверяется с опубликованной к релизу контрольной суммой SHA-256 *до* подмены. Если проверка не прошла, обновление отменяется, а работающая версия сохраняется.
* **Безопасно при сбое.** Если обновление не удалось завершить, продолжает работать прежняя версия. Заменяемый бинарь сохраняется в резервную копию, и если только что установленная версия повторно не стартует, выполняется автоматический откат.
* **С аудитом.** Каждая попытка проверки и обновления — включая отклонённые — записывается в журнал аудита. Пароль никогда не логируется.

---

**Важно:** для использования новой версии не требуется вносить ручные изменения в базу данных, API или конфигурацию. Обновление из панели применимо к стандартной установке как Linux-служба.
