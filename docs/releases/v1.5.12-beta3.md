# Release Notes: v1.5.12-beta3
Release date: 2026-08-14

v1.5.12-beta3 fixes a startup failure that could appear after updating to v1.5.12-beta1 or v1.5.12-beta2 from a version older than v1.5.12-beta1. No manual migration is required.

## Startup fix

Versions before v1.5.12-beta1 stored the self-update boot counter in the `sui.update-pending` file as a plain number. v1.5.12-beta1 switched this file to a JSON transaction marker, and the new parser rejected the old numeric value. The panel then stopped in a restart loop with this error:

```
recover pending self-update: decode pending marker: json: cannot unmarshal number into Go value of type service.pendingUpdateMarker
```

The panel now reads the legacy numeric marker, upgrades it to the current format, and continues the normal recovery path. A binary that repeatedly fails to boot is still rolled back to its backup at the same threshold as before. When the rollback backup (`sui.bak`) is missing, startup still stops instead of booting blind.

## If your server is already stuck

The panel cannot self-update while it is down. Stop the service, move the stale marker aside, and start again:

```
systemctl stop s-ui
mv /usr/local/s-ui/sui.update-pending /usr/local/s-ui/sui.update-pending.broken
systemctl reset-failed s-ui
systemctl start s-ui
```

Then update to v1.5.12-beta3 from the panel. If the new binary still does not start, restore the previous binary:

```
systemctl stop s-ui
cp /usr/local/s-ui/sui.bak /usr/local/s-ui/sui
systemctl start s-ui
```

# Заметки о релизе v1.5.12-beta3
Дата релиза: 2026-08-14

v1.5.12-beta3 исправляет сбой запуска, который мог появиться после обновления на v1.5.12-beta1 или v1.5.12-beta2 с версии младше v1.5.12-beta1. Ручная миграция не нужна.

## Исправление запуска

Версии до v1.5.12-beta1 хранили счётчик попыток загрузки в файле `sui.update-pending` как обычное число. В v1.5.12-beta1 этот файл стал JSON-маркером транзакции, и новый парсер отвергал старое числовое значение. Панель уходила в цикл перезапусков с ошибкой:

```
recover pending self-update: decode pending marker: json: cannot unmarshal number into Go value of type service.pendingUpdateMarker
```

Панель теперь распознаёт старый числовой маркер, преобразует его в текущий формат и продолжает обычную процедуру восстановления. Бинарник, который не загружается несколько раз подряд, по-прежнему откатывается на резервную копию при том же пороге. Если резервной копии (`sui.bak`) нет, запуск останавливается, а не продолжается вслепую.

## Если сервер уже не стартует

Панель не может обновить себя, пока лежит. Остановите сервис, уберите старый маркер и запустите снова:

```
systemctl stop s-ui
mv /usr/local/s-ui/sui.update-pending /usr/local/s-ui/sui.update-pending.broken
systemctl reset-failed s-ui
systemctl start s-ui
```

Затем обновитесь до v1.5.12-beta3 через панель. Если новый бинарник всё равно не запускается, верните предыдущий:

```
systemctl stop s-ui
cp /usr/local/s-ui/sui.bak /usr/local/s-ui/sui
systemctl start s-ui
```

# 更新日志: v1.5.12-beta3
发布日期: 2026-08-14

v1.5.12-beta3 修复了从早于 v1.5.12-beta1 的版本升级到 v1.5.12-beta1 或 v1.5.12-beta2 后可能出现的启动失败。无需手动迁移。

## 启动修复

v1.5.12-beta1 之前的版本把自更新启动计数器以纯数字写入 `sui.update-pending` 文件。v1.5.12-beta1 将该文件改为 JSON 事务标记，新的解析器拒绝旧的数字值，面板陷入重启循环并报错：

```
recover pending self-update: decode pending marker: json: cannot unmarshal number into Go value of type service.pendingUpdateMarker
```

面板现在会识别旧的数字标记，将其转换为当前格式，并继续正常的恢复流程。反复无法启动的新二进制仍会在同样的阈值下回滚到备份。如果没有备份（`sui.bak`），启动仍会停止，而不是盲目继续。

## 如果服务器已经无法启动

面板在停止状态下无法自我更新。先停止服务，移走旧标记，再重新启动：

```
systemctl stop s-ui
mv /usr/local/s-ui/sui.update-pending /usr/local/s-ui/sui.update-pending.broken
systemctl reset-failed s-ui
systemctl start s-ui
```

然后从面板升级到 v1.5.12-beta3。如果新二进制仍然无法启动，恢复之前的二进制：

```
systemctl stop s-ui
cp /usr/local/s-ui/sui.bak /usr/local/s-ui/sui
systemctl start s-ui
```
